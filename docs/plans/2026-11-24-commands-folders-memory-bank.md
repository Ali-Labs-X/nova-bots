# 命令、工作文件夹入口和记忆库

- 日期：2026-11-24
- 代码：`ds-bot/src/client/commands.js`、`composer.js`、`folder-menu.js`、`memory-bank.js`、`browser-actions.js`，`ds-bot/src/host/parts.js`（`clearChat`）、`memory.js`，`app/ui/src/`

## 为什么

换文件夹、看记忆的入口藏在详情和设置里；没有办法把一段对话重新开始；桌面窗口自己画的输入框缺少命令、附件和几种卡片。

## 已定的行为

- 命令：`/clear`、`/stop`、`/folder`、`/memory`，私聊和群聊都有，插件和桌面窗口共用一份。只有整行就是命令时才算命令，`/clear 缓存` 仍是普通消息。
- `/clear`：换到新的一段，不写交接笔记、不带消息。旧的段照常归档、可读、可搜，记忆不动。群聊连同每个成员在群里的会话一起换。正在干活时拒绝。这是「对用户无感、没有手动换段」的唯一手动例外，由用户发起，Bot 没有这个工具。
- 工作文件夹：输入框旁显示当前文件夹，点开即可选、浏览、筛选；「+」和 `/folder` 打开同一个菜单。桌面应用可以把文件夹拖进输入框。检查规则不变。
- 记忆库：一处查看、搜索、添加、修改、删除团队、每个 Bot 和每个群的记忆；可看最近 50 条改动、撤销、导出。经典 Agent 模式的侧栏底部也有入口，只用于查看和管理，经典会话不读 Bot 的记忆。
- 写入走和记忆面板相同的路径：大小限制、拒绝密钥、`journal.jsonl` 都一样。撤销是一次新的改动；之后又改过的条目找不到，会报错。
- 桌面窗口：没有经典模式，不显示切换项；有停止、附件（最多 10 个、20 MB）、`@`、`/side`、各类卡片、语音和 Bot 浏览器。`app/test/ui-actions.test.mjs` 检查共享界面调用的操作在窗口里都存在。

## 不做什么

- `/clear` 不删除消息。
- 不给一个会话第二个可写文件夹：运行时的会话只有一个。

## 已知限制

- 容器里的 Bot 只能看到挂载进去的文件夹。
- `/clear` 之后 Bot 仍能用 `read_own_chat` 找到旧消息。

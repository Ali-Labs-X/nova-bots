# Nova Bots 的愿景

[English](vision.md) | 中文

本文写 Nova Bots 要做成什么、为什么这样做。功能怎么用，见 [README](../README.zh.md)；已定的具体设计，见 [docs/plans/](plans/)；怎么参与开发，见 [CONTRIBUTING](../CONTRIBUTING.zh.md)。

## Nova Bots 是什么

Nova Bots 是一支持久化的机器人团队，基于插件化的智能体运行时构建，开源，使用 Apache 2.0 许可。用户可以和一个机器人聊天，也可以和一支有分工的团队工作：一个或几个 Main Bot 负责组织，每个机器人各做各的事，互相沟通，用户随时能看到谁在做什么。机器人应该有持久化的工作能力，有长期记忆。

## 两种形态

| 形态 | 是什么 |
|---|---|
| `nova-bots` 插件 | 标准插件，装进桌面运行时或 Web 运行时使用。机器人的全部功能都在这里 |
| Nova Bots 桌面应用 | 一打开就是 Nova Bots 本体。自带锁定版本的运行时、自己的 profile 和数据目录，能导入用户已有的团队，也能安装兼容的插件，逐步形成 Nova Bots 自己的插件生态。插件仍然可以单独用 |

两种形态用的是同一份 `nova-bots` 插件。桌面应用的意义在于：Nova Bots 自己掌握 profile 和界面，不再受运行时通用界面和全局配置的限制（见 [运行时让步总账](plans/2026-10-13-dsh-concessions.md)）。

## 十条核心要求

1. **基于运行时，互相独立。** 每个机器人都基于运行时构建，互相独立。
2. **可靠。** 机器人工作应该可靠：思路要对齐、做事要有依据、目标有约束、结果可以验证。要有自我改进能力（待做）。
3. **记忆与持久化。** 机器人应该有持久化的工作能力，即有长期记忆。机器人之间的记忆互相只读（仅 Main Bot 可以修改别的机器人的记忆）。机器人可以管理自己的记忆，用户也可以单独管理每个机器人的记忆。群聊的记忆共享。
4. **权限分级。** Main Bot 有最高权限，可以创建、修改其他机器人。其他机器人没有这些权限（删除必须由用户手动）。可以有多个 Main Bot。每个机器人可以互相调用。
5. **群聊。** 群聊是 Nova Bots 多机器人协作的核心形式，群聊中的机器人可以互相调用，可以有管理员机器人。管理员在群聊中承担管理角色，可以添加、移除成员，默认由管理员回复用户消息。
6. **工作区。** 每个机器人可以单独设置工作区，群聊可以设置统一工作区。机器人应该可以自己设置自己的工作区，即用户一句话即可。
7. **浏览器。** 每个机器人有独立的浏览器，互不影响。要支持导入 cookie（后续做）。
8. **界面与动效。** Nova Bots 应该有精致的前端界面，要有丝滑的动效：一间深空控制舱，极光配色、流动星场，该发光的地方发光。
9. **独立应用。** Nova Bots 应该是独立 App，不为运行时做过多让步。
10. **接入本地 Agent。** Nova Bots 可以把本地的 Agent CLI 接入为机器人，可以互相调用（待做）。

## 取舍原则

- **机器人的正确行为优先。** 运行时某些模式或限制和机器人不兼容时，不为了兼容无限增加复杂度。不得不让步的地方，记进 [运行时让步总账](plans/2026-10-13-dsh-concessions.md)，等桌面应用掌握 profile 后清理。
- **数据留在用户自己的电脑上。** 团队、聊天、记忆都存在本机的 Nova Bots 数据目录里。
- **能验证才算完成。** 行为要有测试覆盖，界面改动要实际看过。

What is Nova Bots

Nova Bots lets you build your own bot army: bots with their own roles, memory and models that collaborate in squads, hand off work and report to a commander. It is open source under the Apache 2.0 license.

Talk to one bot the way you talk to a person, or put a team on a problem: a commander organizes the work, every bot does its own part and talks to the others, and you can see at any time who is doing what. Build your own workflows out of that: one bot researches, one builds, one reviews — they pass the work along.

You can use it in three ways: sign in to the hosted workspace at bots.alilabsx.com, run it yourself in a Docker container, or install the desktop app for Windows, macOS or Linux.

Core ideas

Bot

A long-lived teammate with its own name, role, instructions, model and look. Its work runs in sessions: one for its own chat, one for each squad it is in, and a fresh one when the context fills up. Earlier ones stay readable.

Commander (Orion)

Every new team starts with Orion, the Mission Commander. In the app this is a Main Bot: it has the highest rights and creates, changes and removes other bots. Other bots don't get these rights. You can have more than one commander. Orion also walks you through setup the first time.

Squads

A squad is a group chat that puts several bots on one problem. Every squad has an admin bot that answers by default and calls in the specialists you need. You can also @ any member directly.

Handoffs

Bots hand work to each other with @. The helper posts progress in the squad, finishes on its own, and the bot that asked answers with the result. The squad's details panel lists every handoff and can stop one.

Memory

Each bot keeps its own long-lived memory as plain Markdown; each squad has a group memory that stays in that squad; a team memory is read by every bot. After each turn a review keeps, updates or removes entries. The memory panel lets you read, correct and remove entries. Entries that look like keys or tokens are refused.

Working folder

A bot can work in a folder you choose instead of the team workspace, and a squad can set one folder for all its members. Pick it in the bot's or squad's settings, or just ask the bot. A folder outside the team workspace asks for your approval once.

Get started

Hosted

  1. Go to bots.alilabsx.com/login and sign in with your email and password.
  2. If sign-up is closed, the sign-in page shows Request access; write to Jahanzaib@alilabsx.com.
  3. Your account gets its own engine. Add your model key in Settings → Models, then pick a model for Orion in its details panel.

Self-host with Docker

Docker builds the whole stack — engine, plugin, browser runtime and the interface — into one container. You need Docker 24+ with Compose v2.24+ and a model provider API key.

git clone https://github.com/Jahanzaib211/nova-bots.git Nova-Bots
cd Nova-Bots
cp docker/.env.example docker/.env
./nova-bots.sh start
./nova-bots.sh url

Open the printed login URL once. After that, http://127.0.0.1:13080/ opens the UI directly. The team, chats and model settings live in docker/data/; back up that folder and docker/.env (stop the container first). Host folders, ports, mounts and reboot survival are in RUNNING.md and the Docker guide.

Desktop app

The Electron app runs on Windows, macOS and Linux. It carries a pinned runtime, keeps its data in its own home, and can import an existing team (read only). To run it from source:

# from the repository root
cd app
npm ci
npm run build   # builds the app's own UI into ui/dist
npm start       # starts the app

Packaging, updates and platform notes are in app/README.md.

Plugin

Nova Bots also installs as a plugin into a compatible agent runtime: build or download the nova-bots package and add it through the runtime's plugin manager. Source builds and internals are in ds-bot/README.md.

Models & providers

  • Bring your own key. Bots run on your own model quota. Add a key in Settings → Models, or for Docker set NOVA_API_KEY in docker/.env and run ./nova-bots.sh restart.
  • Your own endpoint. The Docker build works with any Anthropic-Messages-compatible endpoint through NOVA_BASE_URL.
  • One model per bot. Every bot runs on a model of its own from the models the runtime serves. Change it in the bot's details panel, any time.
  • Hosted accounts start with no provider key: you add your own in your workspace, and it stays in your engine. Tenants never inherit the operator's keys.
  • Usage. Settings → Usage breaks token use down by time, bot and model.

Security model

The full threat model is in SECURITY_MODEL.md. The short version:

  • Prompt injection is the main threat. Web pages, files, tool results and messages from other bots are treated as untrusted. The controls aim to stop them from making a bot exceed its rights.
  • Rights are enforced, not suggested. Only a Main Bot (commander) can create, change or stop other bots, squads and folders. Each bot runs with its own permission preset.
  • Secrets stay scoped. A bot's secrets are scoped to that bot and redacted from tool results and from outbound model requests. Memory refuses anything that looks like a key.
  • Sandboxed output. HTML a bot produces renders in a sandboxed frame; desktop bot browsers run sandboxed with their own partitions.
  • Fail-closed sign-in (hosted). Your portal session is the only authority. Every request and WebSocket is checked against it — revoked, forbidden or logged-out accounts are cut off — and without an entitled session there is no engine access. Engine cookies are held by the portal and never reach a browser.
  • One isolated engine per account (hosted). Each account gets its own engine container, its own volumes, and a network where tenants cannot reach each other or the host's private services. Containers drop capabilities and run with no-new-privileges, CPU, memory and process limits.
  • Known limits. Tenants share the host kernel, so a container escape is the boundary. Outbound internet is open because bots need their providers and the web. In the Docker edition, bots have full access inside their own container by design.

FAQ

Is Nova Bots free and open source?

The code is open source under Apache 2.0, and you can self-host it. You pay your model provider for the tokens your bots use.

Does my data leave my machine?

Self-hosted, your team, chats and memory stay in Nova Bots' data folder on your machine; the requests your bots make to your model provider and the web go out as you'd expect. On the hosted workspace, your data lives in your account's own engine volumes on the AliLabsX server.

Which models can I use?

The ones you bring. Add your provider key in Settings → Models; a Docker install can also point at any Anthropic-Messages-compatible endpoint. Each bot can run on a different model.

Can one bot change another?

Only a commander (Main Bot) can create, change or remove other bots. Ordinary bots can call on each other and hand off work, but they can't change each other.

Is there a visual workflow builder?

No. Workflows in Nova Bots are bots coordinating in squads: you set their roles, and they hand work to each other with @ and report back.
